Hex layouts for UK constituencies by Open Innovations and contributors (MIT, see LICENSE), from https://github.com/odileeds/hexmaps: `gb-pcon-2024.json` is `maps/uk-constituencies-2023.hexjson` v1.2 (commit 4d3152010cc5), and `gb-pcon-2010.json` is `maps/constituencies.hexjson` v1.3 (commit 4c15ff979e88), both trimmed to coordinates and borders.

The Canadian House of Commons tile map, `ca-fed-tiles.json`, is our own layout, with one hexagon per riding. Its grids, in `pipelines/ea/hexgrid/ca-fed-{year}.txt`, cover the representation orders first used in 2004 (308 ridings), 2015 (338), and 2025 (343). Each row of a grid file is a row of hexes; odd rows are indented by half a hex, `..` marks an empty hex, and every other token is a province or territory postal abbreviation. The file lists each province's label under its two-digit Statistics Canada code, which is also the first two digits of each riding's code. We drew the 2025 grid by assigning each province a share of hexes around a hand-placed center, then edited it by hand; the 2015 and 2004 grids drop hexes from the edges of the 2025 grid. `ea hexes` places each election's ridings inside their province's hexes by matching each riding's position within the province, taken from our riding shapes, to the hex in the same relative position. Each grid in the file carries its province borders, as hex edges in the same format as the UK files, and a label hex for each province; `years` gives the grid and the hex of every riding for each general election from 2004 to 2025.

The French National Assembly tile map, `fr-circ-tiles.json`, is our own layout too, in the same format. Its one grid, `pipelines/ea/hexgrid/fr-circ-2012.txt`, holds the 539 constituencies of metropolitan France, Corsica included, for the boundaries first used in 2012; grid tokens are department numbers, which are also each constituency's code without its last two digits. We cut the outline from the real shape of mainland France, with one hexagon per seat, assigned each constituency to a hexagon by its real position, and moved hexes between neighboring departments until each one was in one piece, then edited the result by hand. The grid has two kinds of borders: `states` runs between the 13 regions and `inner` between departments within a region. The 27 overseas and 11 abroad constituencies are not on the grid, since the page already shows them apart from the map. `years` covers the elections of 2012, 2017, 2022, and 2024.

The Bundestag tile map, `de-wk-tiles.json`, is our own layout as well, drawn the same way as the French one, from the real outline of Germany. Its grid, `pipelines/ea/hexgrid/de-wk-2025.txt`, holds the 299 constituencies (Wahlkreise) of 2025, the only year we have their shapes for; grid tokens are the usual two-letter abbreviations of the 16 states. A constituency's code carries no state prefix, so `ea hexes` takes each constituency's state from its parent `de.land` area, and each year in the file lists that state's two-digit code for every constituency under `regions`. We edited the grid by hand so that Brandenburg wraps around Berlin on the north and east.

State tile maps, in `states.json`, have one hexagon for each state-level unit of a country. They carry the results of statewide races, such as the US president by state, the Senate, and governors. Each country has one grid, `pipelines/ea/hexgrid/states-{polity}.txt`, in the same format as the district grids, and `ea hexes` keys each hex by its area code and keeps the grid token as the hex's label. The US grid holds the 50 states, DC, Puerto Rico, and the four territories, with postal codes as tokens. We drew it ourselves: a script cut a mask from the real outline of the lower 48 states, assigned each state to a hex by its position, and swapped states to keep real neighbors next to each other; we then placed every hex by hand. The layout keeps 88 of the 109 land borders between the lower 48 states and DC. Alaska and Hawaii sit at the left edge, and Puerto Rico and the Virgin Islands at the bottom right. An election page shows only the units that held a contest in that election, and it leaves the hex of a unit without a result in the current race blank.

The same file holds our own state tile maps for Switzerland's 26 cantons, Brazil's 27 federative units, and Turkey's 81 provinces, in `states-ch.txt`, `states-br.txt`, and `states-tr.txt`. Each one started from the same outline script and was then edited by hand so that the grid keeps the country's shape: Switzerland is wide, with Geneva at its southwestern tip and Schaffhausen above Zurich; Brazil's three southern states form a tail; and Turkey has Thrace in the northwest, Sinop on the Black Sea coast, and Hatay in the south. Swiss and Brazilian tokens are the canton and state abbreviations. Turkish tokens are the two-digit province codes, which are also the license plate numbers, and they are used as the hex labels. Provinces that no longer exist are not on the Turkish grid. A province counts as holding a contest when one of its electoral districts does, as with Istanbul's three districts.
